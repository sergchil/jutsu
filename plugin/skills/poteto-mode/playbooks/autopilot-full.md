### Autopilot-full

**You own the verdicts, never the PRs. One owner carries each PR from build to merge, and nothing merges until your swarm, which never wrote the code, has proven the code that lands.**

A verdict covers one patch and green CI covers one head. Step 4 runs a full swarm once, and again only for a major change. The patch-id rule in `playbooks/shipping.md` can carry a lane's result, and every new head needs its own green CI.

1. **The operator's gates come first.** The grant covers only the queue's items, so items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2. **Spawn one owner per PR, and keep its work where a replacement can find it.** Resolve the forge once for the program. GitHub CLI (`gh`) is the forge for every PR operation. Never require Graphite (`gt`). Each owner, in its own worktree, builds, opens its PR per `playbooks/opening-a-pr.md`, proves the change on the real artifact (the **prove-it-works** principle, `../../../principles/principle-prove-it-works.md`), babysits to green per `playbooks/babysit.md`, and merges once steps 4 and 5 clear it. In T3 each owner is a launched thread per [the runtime's Isolation](../references/runtime.md#isolation), because it must watch its own PR and delegated children cannot. Launch it with `t3_thread_launch`, a `worktree` `workspaceStrategy` whose `baseRef` is trunk's commit SHA (never a T3-made `t3/<hash>` branch name, per the runtime), the brief in `message` (opening with the router's absolute path and `Read it in full before any work.`), and a `modelSelection` from the code role. Leave `runtimeMode` and `interactionMode` unset so the owner runs in your modes. Launch has no retry key, so after a lost response check `t3_thread_list` before you launch again. A launched thread never wakes its launcher, so the brief carries your thread id and says to send each report below with `t3_thread_send` and `mode: "queue"` to it, and to stop when that call is refused. Outside T3 each owner is a background `Agent` in its own worktree. Such an owner has no `/loop`, so it babysits by rerunning the bare watcher in the foreground (`playbooks/babysit.md` step 6). Before the first owner starts in T3, confirm with `t3_thread_configuration` that this thread runs in `auto` or `full-access` mode, and ask the operator to switch it if it does not. A child's modes can never be broader than its parent's, so under a narrower mode every owner stalls on approvals. Those modes approve tool calls silently, so you hold the Always-pause list yourself ([the runtime's Questions](../references/runtime.md#questions)). Owners and their children run every command in the foreground, since a Claude child that leaves a background shell running can end its turn early.

   Open the PR early so CI and bots run alongside the work. The code is ready only after the slop-strip (deslop per [the runtime's Missing companions](../references/runtime.md#missing-companions)) and the `/jutsu:no-comments` pass (the **no-comments** skill, `../../../skills/no-comments/SKILL.md`), so the full swarm runs on finished code. Then rebase onto current trunk and report the code-ready head before self-proof, so verification runs on the base the patch lands on. Report every later head, and merge-ready once self-proof, CI, and babysit are done. Fix rounds stay on that base unless trunk conflicts or breaks CI, because each rebase restarts CI. Run the repo's checks for the touched paths (the ones its CLAUDE.md and AGENTS.md files and rules name) on the committed head before the code-ready push and before a later push that needs a verifier. Before each commit or push from its worktree, the owner stops every child that writes there, grandchildren included.

   Assume the owner's session dies. Soon after starting, push and start a decision trail in the root's store (`.jutsu/<slug>/` per [the runtime's Store](../references/runtime.md#store), by the absolute path the brief names) per the **show-me-your-work** skill (`../../../skills/show-me-your-work/SKILL.md`), then push after every unit worth keeping. Whoever spawns a subagent records its id, state, and a stuck-after runtime from past runs of its kind in that store, so the root can probe it if the parent dies. Force-push only your own branch, with `--force-with-lease` pinned to the SHA you last pushed or took over, and on any push you did not make, stop and report to the root.
3. **Run owners in parallel off trunk, never stacked,** so each PR lands on its own.
4. **Swarm-verify once.** A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head. Fan out independent verifiers at the code-ready SHA per the **swarm** skill (`../../../skills/swarm/SKILL.md`). Record the model and effort each lane actually ran at, not the ones you asked for ([the runtime's Roles](../references/runtime.md#roles)). For a `delegate_task` lane, `task_status` names the model and `t3_thread_configuration` on its `childThreadId` names the effort. For an `Agent` lane, take the model from its transcript's assistant records and record the effort you passed. They re-run the gates, prove the load-bearing behavior live on the real surface (on the matching surface in [the runtime's Proof surfaces](../references/runtime.md#proof-surfaces), such as T3's `preview_*` tools or the terminal) or a named driver, and audit the diff. The verdict is not clean without the live lane, or before you audit the merge-ready report's receipts, because no lane trusts a claim it has not checked. When no independent lane could run, the verdict is not clean. Record `BLOCKED: independent review` and name the lanes that did run.

   Send every proven finding, whatever a lane labeled it, to the owner in one fix-forward (a `t3_thread_send` with `mode: "queue"` to a launched owner), with a red test across every site with the same defect. A defect trunk shows without the PR is recorded against trunk and does not gate the PR, but one the PR copies or newly reaches is the PR's own. Never push a fix yourself, because each branch has one writer. Replace a stuck owner instead.
5. **The owner merges only what you verified, tested on the trunk it lands on.** Green CI alone never authorizes a merge. Once the swarm's lanes have started, merge prep rebases onto current trunk, reports the new head, and waits for green CI.

   Right before merging, fetch trunk and ask whether its changes can affect the patch, because rebasing for every trunk move never ends. Rebase and wait for CI when the code that would land was never tested, as with a conflict, a file both sides changed, or a change to which checks run for the PR. A lockfile both sides changed needs no rebase when a frozen install passes on the merge result and the packages the PR changes resolve there as on the head, because that install tests the lockfile that would land, and a failing install means the rebase must repair it. When trunk changed a caller of the patch or something the patch depends on, such as code it calls or a dependency version, run the patch's checks on the merge result and merge on a pass. Otherwise merge. If trunk would force a third rebase past merge prep, hold and report to the root, which sequences the colliding work.
6. **Run the root layer.** Anything that loosens a gate, such as a raised budget or an allowlist entry, needs a verifier's proof and then your fresh countersign, because the owner is the one who wants green. Under a grant that covers approvals, that countersign is the approval, and the owner's record of it points at your countersign for a lane to check. A disabled or soft-failed check always comes out, because it stops guarding every case. Never give or bypass an approval the forge enforces, because no countersign covers it.

   On the operator's go, arm an hourly audit tick until no delegated work is left, because long runs drift and agents stall silently. Arm it per [the runtime's Waking](../references/runtime.md#waking). In T3 that is `schedule_task` with `schedule: {"type":"interval","everyMs":3600000}`, bound to this thread, because an unbound run starts a fresh thread from `main`. Report the returned cadence and next run time. Outside T3 it is `/loop 1h`. The scheduled task survives a T3 restart and `/loop` does not. Each tick re-reads this playbook from the installed plugin, `<router-dir>/playbooks/autopilot-full.md`, where `<router-dir>` is the absolute directory of poteto-mode's SKILL.md that the tick prompt names, and fixes drift, such as an unreported head or an unrecorded agent, by having its owner record it, because drift is a gap in the record, not a stall. It probes every agent, down to the leaf lanes (`t3_thread_read` on a launched owner), and judges each by its side effects, because status text and summaries can hide a stuck child. In T3 also watch each owner's PR with `watch_pull_request`, since a launched owner never wakes you. A merge ends that watch without a wake, so the tick is how you learn of a merge the owner did not report. An agent is stuck when it errors, cannot start turns, or shows nothing new past its stuck-after runtime, and so is an owner that has neither pushed nor written a trail row by the first tick. In Claude's agent list `completed` means the completion was notified, not that the agent exited. A delegated child can finish its turn and leave its run open, so its completion wake never comes. A bounded `t3_thread_wait` catches it. One waiting on you or the operator is not stuck, so answer it. In T3, `t3_pending_request_list` on its thread finds the question and `t3_pending_request_respond` answers it. Send one only the operator can answer to the operator. Replace a stuck agent at once, without waiting for its stop to land. Stand it down with `TaskStop` for a subagent, `task_cancel` for a delegated child, and as in step 7 for a launched owner, since `t3_thread_interrupt` does not stop async children. Confirm with `git status` that it stopped writing before its replacement takes the work. End the tick (`delete_scheduled_task`, or stop the `/loop`) only when no delegated work is left. Then settle each finished owner thread that T3 has not settled on merge with `t3_thread_organize` and `action: "settle"`. A tick that changed something for the operator ends by catching them up per the **ketchup** skill (`../../../skills/ketchup/SKILL.md`), and one that changed nothing stays quiet.
7. **Stand down at once on the operator's stop.** A hold reaches every owner as a zero-writes order. In T3, `t3_thread_interrupt` each owner, then `t3_thread_send` it the order. An interrupt does not stop async children, so the order tells each owner to stop its subagents and `task_cancel` its delegated children first. Cancel your own delegated lanes with `task_cancel`. Each reports where it stands and keeps its brief until the operator releases it.

**Reply:** catch the operator up per the **ketchup** skill, covering each PR's state and verdict, what merged, countersigns and why, and open operator gates, with links to each PR and the trails.

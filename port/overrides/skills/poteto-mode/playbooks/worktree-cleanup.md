### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (`{{plugin}}/principles/principle-build-the-lever.md`). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.t3/worktrees/myrepo/x` (`{{plugin}}/principles/principle-encode-lessons-in-structure.md`). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, read from the Claude transcripts of this repo's checkouts ([the runtime's History](../references/runtime.md#history)), then suggests a bucket. `hold-local` means files that exist only in this folder: untracked files, or ignored ones such as `.env`, logs, and build output. `hold-unpushed` means commits that are on no remote: ahead of the remote branch, on no remote branch, or detached and not on the base ref. Push them or get a decision first. A closed-but-unmerged PR is not evidence the work is safe, and a merged PR covers only the commit it merged. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (`{{plugin}}/principles/principle-prove-it-works.md`). Get that set from the user or the T3 sidebar and cross-check every candidate. In T3, `t3_thread_list` with `settled: false` lists the open threads, and `t3_thread_read` names each one's `worktreePath` and `branch`. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts or T3 threads and report whether the chat is pinned or ongoing and which worktrees it touches (`{{plugin}}/principles/principle-guard-the-context-window.md`, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Pick each subagent's reasoning level (`effort`) and fast or standard speed for the job, per the Subagents section and [the runtime's Roles](../references/runtime.md#roles).
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits: show the diff. `untracked:N` is files git has never seen, and `ignored:N` is paths a `.gitignore` rule matches, such as `.env`, logs, or `build/`. List both with `git -C <path> status --porcelain --untracked-files=all --ignored=matching`, and say which look regenerable (dependency installs, build output) and which do not (secrets, logs, notes, run artifacts). `unknown` means git could not read the folder, so treat it as `wip`. None of this is on any branch, so it is gone once the folder goes. Get a decision on each before removing anything. Removing a clean worktree is recoverable from its branch. Per Autonomy, clean, merged, and not-in-use proceeds. `wip`, `untracked`, `ignored`, `unknown`, `hold-unpushed`, and in-use pause.
5. Prune the confirmed set. Per path, run a plain `git worktree remove <path>`. It deletes ignored files with the folder, so run it only after the user approved them in step 4. It refuses on tracked edits, untracked files, or a locked worktree, and that refusal is the stop: never add a force flag and never delete the folder by hand. When the user approved dropping specific untracked files, delete exactly those with `git -C <path> clean -f -- <file>...`, which never touches tracked or ignored files, then run the plain remove again. If it still refuses, something changed since the audit, so stop and re-run it. Branch refs survive, so commits on the worktree's branch are kept. A detached worktree's commits are not. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, `~/Library/Application Support/Cursor` when Cursor is installed (`state.vscdb.backup`, and `snapshots/roots/<root>` where a `<root>` named for a folder you opened as a workspace balloons), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
